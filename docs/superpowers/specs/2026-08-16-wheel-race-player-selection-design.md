# 车轮赛选手选择界面设计

## 目标

将车轮赛“选择下一场 PK”弹窗从两个下拉框改为与 `docs/prototype_v3.html` 一致的竖向选手列表。用户可以直接点选两名选手，快速安排下一场对局。

## 界面结构

弹窗按从上到下排列：

1. 说明文字：提示车轮赛允许自由选择两名选手，不限制组合顺序和比赛场次。
2. 当前选择摘要：显示“已选择 0/2”以及两名选手的 PK 摘要；未选满时使用占位文案。
3. 本轮规则信息：显示 `BO1` 和 `11 分`，与车轮赛默认规则保持一致。
4. 竖向选手列表：每个选手是一个可点击的有样式 item，显示头像、姓名和“可选/已选”状态。
5. 操作按钮：保留“稍后安排”和“开始本轮 PK”。

## 交互规则

- 点击未选中的 item：加入选择集合，item 边框变为 2dp `score_blue` 蓝色，并显示“已选”。
- 再次点击已选中的 item：从选择集合移除，恢复普通边框，并显示“可选”。
- 同时最多选择两名选手；已经选满两人时点击其他 item 不改变选择，并提示“最多选择 2 名选手”。
- 只有恰好选中两名选手时，“开始本轮 PK”才可用。
- 开始 PK 后，按列表中被选中的顺序设置玩家 1 和玩家 2，沿用现有 BO1、11 分、每 2 分换发的车轮赛规则。
- “稍后安排”继续进入车轮赛等待状态，不结束车轮赛会话。
- 选手池不足两人时，继续沿用现有校验并提示至少需要两名选手。

## 实现边界

- 新增一个无 Android 依赖的选择状态对象，负责 toggle、最多两人和完成状态，便于单元测试。
- `MainActivity.showWheelPairChooser()` 负责构建 item、同步选中视觉状态、更新摘要和触发已有 PK 启动流程。
- 不改变车轮赛选手池的保存格式、对局历史、比赛引擎或车轮赛会话生命周期。
- 新增普通 item 和蓝色选中 item 的 drawable，保持现有 8dp 圆角和页面色板。

## 验证

- 单元测试覆盖：首次选择、第二次选择、点击已选项取消、第三项被拒绝、两人选满状态。
- 构建并运行现有 `testDebugUnitTest` 与 `assembleDebug`。
- 在 Android 设备上打开车轮赛选择弹窗，验证列表纵向排列、蓝色边框切换、取消选择、按钮启用条件和开始下一场 PK。
