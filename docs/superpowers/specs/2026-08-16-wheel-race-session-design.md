# 车轮赛会话与下一场 PK 设计

## 目标

车轮赛由多名选手组成选手池，每场 PK 结束只结束当前 PK，不结束整个车轮赛。用户可以在任意时刻重新选择两名不同选手开始下一场，不要求固定顺序，也不限制同一对选手再次比赛的次数。

## 状态模型

| 状态 | 当前小场 | 车轮赛会话 | 主界面行为 |
| --- | --- | --- | --- |
| 待选择 | 无 | 进行中 | 显示“待赛 + 选择下一场 PK”入口 |
| PK 进行中 | 有 | 进行中 | 显示选手、比分和计分按钮 |
| PK 结束待安排 | 已结束 | 进行中 | 显示结果；关闭弹窗后保留车轮赛入口 |
| 车轮赛结束 | 无 | 已结束 | 清理当前会话，保留历史记录 |

当前小场的 `MatchEngine` 生命周期与车轮赛会话分离。小场结束时不能直接依赖 `KEY_ACTIVE=false` 判断车轮赛结束；需要单独持久化车轮赛会话是否仍在进行。

## 交互流程

1. 从车轮赛设置录入至少两名选手，进入“选择下一场 PK”。
2. 选择器展示所有可选选手，用户选择两名不同选手；选择相同选手时阻止开始。
3. 选择完成后创建 BO1 小场并进入主计分。
4. 小场结束后保存单场历史记录，并显示结果弹窗。
5. 结果弹窗提供“选择下一场 PK”和“稍后安排”两个继续入口；关闭弹窗等价于“稍后安排”，不清除车轮赛会话。
6. 主界面待赛入口始终可用，点击后可重新打开选择器。
7. 只有用户明确点击“结束车轮赛”才清除车轮赛会话；历史记录不受影响。

## UI 约束

- 车轮赛主界面使用与现有赛事控制台一致的卡片风格。
- 待赛入口使用“待赛 + 选择下一场 PK”文案，避免与团队赛入口混淆。
- 选择器使用两张可增加视觉层级的选手卡或两个带样式的选择项，分别代表选手 1 和选手 2。
- 选择器明确提示“不限制顺序和对局次数”，并在相同选手时给出即时提示。
- 结果弹窗区分“当前 PK 已结束”和“车轮赛仍在进行”，避免用户误认为整个车轮赛已结束。

## 持久化与兼容

- 新增独立的车轮赛会话标记和当前选手池持久化状态。
- 旧版本仅有 `KEY_ACTIVE` 时，若模式为车轮赛且选手池有效，则恢复为“待选择下一场 PK”，不恢复为已结束。
- 车轮赛每场 PK 继续以独立历史记录保存。
- 不修改 `MatchEngine` 的 BO1 计分规则，避免影响正规赛、娱乐赛和双打。

## 验收标准

- 小场结束后关闭结果弹窗，车轮赛入口仍可见。
- 不点击“下一场 PK”时，等待或重启应用不会让车轮赛消失。
- 可任意选择两名不同选手，允许重复选择已进行过的组合。
- 选择同一名选手两次不能开始 PK。
- 明确点击“结束车轮赛”后，主界面回到未开始状态，历史记录仍可查看。
